# Scientific workflow audit — 16 September 2026

UncertaintyCat's main workflow gaps were disagreements between the object on screen, the object submitted
for computation, and the evidence recoverable after navigation. This change makes those boundaries
explicit, repairs production surrogate execution, and makes empirical distribution fits repeatable.

**Audit snapshot:** implementation and focused regressions are complete. The final delivery report
records final aggregate browser/full-stack results, exact-commit CI, automated release verification and
production cleanup after deployment; this source document does not claim those later steps are complete.
The user's final explicit instruction authorizes committing and pushing directly to `main`, superseding
the pasted brief's branch/PR instructions. No pull request or manual deployment is part of this delivery.

authority documents, the route/studio/report implementations, the catalog and existing journey tests.

All studios remain project scoped. The current catalog has **15 plugins**: 11 direct-composer methods and
four dedicated-workflow methods (`morris`, `pce`, `gpr`, `calibration_nlls`). Direct methods are propagation,
EDA, correlation, ANCOVA, Sobol, FAST, global HSIC, target-domain HSIC, Taylor, convergence and reliability.
Availability is still determined by core/Worker scientific assessment, including independence,
continuity, output variability and existing resource limits; React does not become numerical authority.

## Scientific and security boundaries

UX30 was reproduced before modification: with the same synthetic samples and initial global seed, the
Normal p-value for one column changed from approximately 0.969031 when ranking to 0.972028 when composing;
an unreset repeat produced approximately 0.960040. This was deterministic evidence of unmanaged
Monte Carlo state, not chart rounding or AI interpretation.

Fitting 1.1.0 assigns each named column/family the lower 31 bits of the first four SHA-256 bytes of the
compact UTF-8 JSON tuple `[seed, column, candidate]`. The request/result retain the seed, default 42.
OpenTURNS factories, estimators, goodness-of-fit methods, criteria, copulas and thresholds are unchanged.
Historical results are neither rewritten nor assigned an invented seed/version. Repeatability does not
make a goodness-of-fit p-value exact or establish the data-generating distribution.

Authentication allowlists, ownership predicates, model-source isolation and AI/numerical boundaries
remain enforced. UX32 strengthens error privacy. The project-history migration adds forward-only index
support; no applied migration was edited. Cancellation preserves prior numerical JSON unchanged.
See [architecture](../ARCHITECTURE.md) and [scientific validation](../SCIENTIFIC_VALIDATION.md).

## Final source-handoff and text-enlargement checks

UX06 also covered a late source-handoff race: before an explicitly requested saved definition arrived,
authoring could expose a fallback definition; browser Back between source URLs could reuse pending
validation state. Only Workspace now remounts on pathname/search changes. Its authoring and validation
remain disabled until the requested saved model, reference, or retained Data Lab draft has hydrated.
Loading and unavailable states are explicit, with retry/recovery; hydration occurs once so a background
refetch cannot overwrite edits. Focused delayed-response tests verify the exact submitted source,
failure/retry, missing draft/reference rejection, and Back while an earlier validation is pending.

Five focused tests passed on an isolated port 4177, including keyboard-only project creation, model
naming, guided validation, method selection, threshold editing and Run focus at 1440×900. The initial
root-font setting `html { font-size: 200% }` was verified as 32px and a real rem-sized progress label
was verified to double. Because most application typography uses fixed pixels, the composer test then
removes that override, snapshots every HTML element's computed font size and numeric line height, and
applies exactly twice each original value. This prevents cumulative scaling of nested elements and
explicitly exercises fixed-pixel text. Assertions verify actual 2× font sizes for the Run button, sample
budget input and method-card labels, horizontal containment of the document/method controls/cards,
and working keyboard threshold changes and Run focus after scaling. The augmented test passed again
with a retained full-page screenshot (1/1, 16.0 seconds); the screenshot was visually reviewed.

The first doubled-text screenshot exposed clipped guided-builder fields. UX33 was extended with a
narrow repair: variable rows wrap their actual fields using text-relative minimum widths, rather than
reserving four parameter columns for every distribution; output name/formula fields wrap similarly.
The final test measures each displayed native-select option and input value using its computed font,
allowing for padding and native controls, and verifies that the text fits and every field stays inside
the authoring pane. Parameter-label overflow is also checked. A separate regression covers the assessed
model pane at 1280, 1440, 1920 and 390 pixels. Both final focused tests passed (2/2, 13.5 seconds), and
the repaired enlarged screenshot was visually reviewed.
These are DOM simulations, not native browser text-only zoom or full WCAG resize certification; the
assertions establish the named authoring/method flows rather than every label across the application.
Synthetic screenshots and output remain untracked under `work/zoom-builder-final-results`.
